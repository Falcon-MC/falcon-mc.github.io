Plugins

Publish a plugin

Sign in with GitHub to publish. The store asks GitHub who you are and whether you belong to Falcon-MC; it never writes to your account.

  1. The plugin lives in a public GitHub repository you administer, with its plugin.json at the root.
  2. Each version is a GitHub release with the files a server loads, each at most 32 MB: one .wasm for a Wasm plugin, one .jar for a Java plugin, or for a native plugin one library per platform: .so for Linux, .dll for Windows, .dylib for macOS. Put x86_64 or arm64 in the name when you ship both. Drafts and pre-releases are skipped.
  3. Choose one to three categories; you can change them later.
  4. Optionally, give the plugin a logo and a banner in plugin.json: "icon": "assets/icon.png" and "banner": "assets/banner.png", paths in the repository. PNG, JPEG or WebP; the logo square, 64 to 512 pixels, at most 256 KB; the banner about 3:1, 600×150 to 1600×600, at most 1 MB. The store keeps a copy and shows it once an administrator approved it; a new one, pushed to the default branch, shows after Check for new releases and a new approval.
  5. An administrator reads the plugin before it is listed. After that, new Wasm versions are listed once the store has checked them; native and Java versions wait for an administrator.
  6. A release file replaced after it was checked hides its version until it is checked again.
